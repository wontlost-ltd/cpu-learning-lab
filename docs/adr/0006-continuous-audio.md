# ADR 0006：连续 PCM、可选麦克风与显式反馈

## 状态

P4 第二步：连续输入软件管线、PortAudio 默认麦克风入口已实现。真实麦克风、噪声质量、目标设备延迟和能耗验收仍待硬件实测。默认构建只有标准库／系统 API；可选麦克风构建另链接已安装的 PortAudio，不打包或下载第三方源码。

## 统一特征入口

P4 的 `readWave` 现在解码为 PCM 后调用 `analyzePcm16`。连续流也调用该函数，保留相同的特征、阈值、PCM 指纹和 `CPUAI_AUDIO1` 存储格式。旧音频教学模型可以直接使用，不引入新的预训练权重。

`PcmWindowStream` 单线程拥有状态；支持 8..48 kHz、50..2000 ms 非重叠窗口，采样率乘窗口毫秒必须整除 1000。默认 8 个待取窗口，可配置 1..32；单次 feed 最多 65536 帧，最多处理 32 个窗口。窗口保留 PCM，便于明确选择的用户教学，不默认写入磁盘。

## 帧确认、暂停和断流

`feed` 返回已消费帧数、产生窗口数和停止原因。队列满、工作切片结束、取消或暂停均不消费剩余输入；调用方保留未确认部分并在排空后重试。队列不静默淘汰旧窗口。取消在窗口之间检查，不中断一次特征提取。

窗口携带进程内递增 sequence、segment 和片段内 start_frame；它们不是跨设备永久 ID。普通 pause/resume 声明可能丢失设备音频，清除未完成窗口并开新片段。只有调用者保证生产端无损暂停时才使用 `resume(true)`。设备 overflow 同样创建新片段，避免把断点两侧的样本拼成一次学习证据。已完成的排队窗口保留原片段身份。

`finish` 只丢弃未完成尾窗口并计数，保留已完成窗口供读取；幂等，不能重新启动。每会话最多消费 10¹² 帧，避免时间／序号溢出；队列与 PCM 窗口有界不等于进程 RSS 硬上限。

## 原生入口与调度

`cpu-listen --stdin|--microphone RATE WINDOW_MS MODEL MAX_WINDOWS` 输出 JSON Lines。MODEL 为 `-` 表示尚未教学。stdin 是没有文件头的单声道有符号 PCM16LE，不能直接喂 WAV；调用者保证采样率和通道一致，不自动重采样。默认麦克风使用设备提供的本机 int16 数据。

stdin 适配器在 POSIX 用 poll，在 Windows 用 pipe readiness／文件读取。跨读操作的单字节尾部暂存，到真正 EOF 仍不足一帧才报错；空输入正常结束。闲置管道每 20 ms 检查停止标志。Windows stdin 需要管道或普通文件，不支持控制台文本输入。

麦克风采用 PortAudio 的阻塞读接口，预先轮询可用帧，每次读 256 帧。等候时约每 5 ms 检查停止标志；处理、推理与文件写入都在普通调用线程上，不占用用户音频回调。此实现优先清晰可验证的语义，不承诺最低延迟或硬实时；设备驱动仍可能阻塞。SIGINT/SIGTERM 请求协作停止，MAX_WINDOWS 限制输出数，不是墙钟超时。

overflow 时丢弃该次 256 帧返回块、清除半截窗口、输出断流事件。驱动实际丢失帧数未知，JSON 用 null 表示，不伪造绝对时间。`discarded_capture_frames` 仅统计调用方已经读到但放弃的完整帧；未知设备丢帧不包含在此数中。处理慢或 stdout／磁盘阻塞仍可能导致设备 overflow；下一读取可报告，但这不是无损采集保证。

输出窗口以帧和片段定位，没有承诺硬件时间戳或自动接入跨来源观察对齐。需要后续采集时钟映射协议，才可安全融合手机／穿戴的多个流。

## 显式录音教学与模型更新

默认只输出预测及指纹，不保存原始音频。`--capture NEW_DIR MAX_FILES` 是用户明确选择的有界录制：目录必须新建、不覆盖已有目录，最多 256 个完整窗口（每个最多 2 秒）；达到上限后继续识别但停止录制。采集路径在每个窗口的 JSON 中给出。没有自动循环覆盖、自动上传或后台伪标签。

用户可在另一个 `cpu-learn` 进程中 `audio-load`，对录下的窗口执行 `audio-teach`（同 ID 用于纠错），再 `audio-save`。监听端显式启用 `--reload` 后，每个完整窗口边界读取指定模型，完整验证成功才替换当前快照。读取失败保留上一次有效快照并计数；每个预测输出模型 revision。没有自动选择“更优”模型、跨模型全局版本排序或发布认证，同修订号的另一个合法文件也可以替换。

现有 save 不是跨进程事务。用户宜先写同目录临时文件，再使用平台支持的原子替换；失败加载的保留策略防止常见半写入状态影响当前预测，但不构成认证或并发写保证。反馈只有来自用户的明确标签，不把预测自动当训练真值；独立音频考试仍由 P4 命令执行，实时加载本身不等于通过考试。

## 验证与度量

单元测试：不同分块的指纹一致、队列满时精确重试、暂停／无损续算、断流不拼接、取消、切片、结束和参数上限。

集成测试：连续 PCM 识别、有限录制 → 用户教学 → 新声音识别、窗口边界模型修订替换、损坏更新保留旧模型、奇数字节传输分块／损坏 EOF、最大窗口数、POSIX 闲置管道 SIGTERM 停止。CI 默认三平台运行；额外 Linux 作业安装真实 PortAudio 开发包，编译链接麦克风适配器并运行相同 PCM 测试。CI 不冒充有可用麦克风；macOS／Windows 的可选 PortAudio 链接与设备行为仍未验收。

`processing_ms` 计量最后一个输入切片的组窗、特征提取、可选模型加载和推理，不含此前片段拷贝、设备等待、捕获文件写入或 stdout；因此不是端到端采集延迟。汇总给总处理时间和最大值；基准脚本另记录完整子进程／管道墙钟时间。记录环境、合成音频、未教学模型，不能据此推断复杂分类负载、实时质量或功耗。

## 待实测门槛

至少准备两个真实声音标签、未教学未知类与独立录音，在安静／噪声、不同设备与录音日期下分别报告准确率、拒识率、误接受与用户纠错后的改善。保存原始测试清单与模型修订。

在目标手机／电脑上记录窗口大小、采样率、持续时间、overflow、尾帧／放弃帧、处理分位数、采集到预测的实际延迟、进程内存。固定亮度、无线状态与电源条件，分别测空闲和采集＋推理的功率／能量差；当前没有提供或声称完成这些硬件结果。

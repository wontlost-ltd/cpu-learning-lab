# ADR 0007：持久设备事件与幂等文件同步

## 状态

P5 第一部分：可靠存储和同步语义的原生参考实现。没有手机／手表／眼镜应用、蓝牙／HTTP 服务、远程身份认证或 ChronoSynth 接口；文件同步只模拟两个节点之间的交付。P4 的真实麦克风、噪声泛化、Mac 本机功耗验收继续保留。

## 事件身份与来源

`DeviceEvent` 的稳定身份为 `(device, session, sequence)`。设备和会话 ID 为 1..64 字节 ASCII 字母、数字、`-_.`；sequence 在 1..10¹²。同 ID、相同载荷是重复；同 ID、不同载荷是冲突，整批拒绝，不覆盖原经验。接收端允许乱序，不用最高序号代替已收到集合。

载荷保存 P4 音频特征、PCM 指纹、采样率、帧数、片段号、片段内起点与日志记录时间。`recordedAtMs` 是处理端写事件前的墙钟时间，不是硬件采集时间或经同步的跨设备时钟，不能直接拿来声明因果或精确对齐。

空 `userLabel` 表示观察；非空标签必须由调用者显式提供。监听器不把预测标签写成教学真值。`cpu-sync record` 记录用户提供的 WAV 特征和可选标签；这一版本只保存／复制经验，不自动更新 AudioLearner，不宣称学习副作用恰好执行一次。后续标签应用、纠错关系、事务模型与独立验收需要另一个协议。

## 日志与确认边界

每个日志含一个固定节点身份。二进制帧为 magic、长度、头 CRC32、载荷、载荷 CRC32 和提交标记；长度最多 128 KiB，载荷使用经典数字 locale、17 位浮点和 quoted 字符串，首帧必须是版本化身份。CRC 是损坏检测，不是认证或签名；PCM 指纹仍采用 P4 的非密码学 FNV。

追加事件／回执前，先完整校验批次并准备下一内存状态。写完整帧后执行系统同步，再用无分配的 map swap 更新状态并返回成功。I/O 异常后日志对象进入不可继续操作状态，必须关闭重开；不把不确定写入当作失败回滚并继续覆盖。重开时重新同步完整尾记录，之后才允许对重复交付返回确认。

系统调用：Linux fsync，macOS F_FULLFSYNC，Windows FlushFileBuffers；POSIX 同步父目录元数据。同步失败不退回普通 flush 并继续确认。Windows 未实现等价目录同步。这里验证进程终止与日志格式恢复，不承诺磁盘硬件、文件系统、备份工具或物理断电后的绝对可靠性；这些需在目标设备实测。

打开时扫描帧并校验版本、长度、CRC、载荷与资源边界。不足一个完整末帧的尾写入会截到最后完整帧，并同步截断结果。完整但损坏的帧报错、保留文件，不自动丢掉可能已确认的历史。没有完整身份的非空文件拒绝重置；空日志仅可通过显式节点 ID 初始化。

每个文件由单个进程独占：POSIX flock 非阻塞锁，Windows 不共享文件句柄。采集进程退出后再做同步；当前不支持边采集边运行另一个 cpu-sync 进程读取同一日志。不保护绕过文件锁的外部修改，也不支持网络文件系统或任意数据库备份的一致性保证。

## 交付、回执和断线恢复

1. 发送端选择最多 128 条事件。
2. 接收端校验全部身份／载荷，持久化新事件；已存在相同事件不重复追加。
3. 接收成功后，发送端持久化目标节点回执。
4. complete 仅表示当前两个日志之间的全部源事件均存在且已确认，不代表联网、模型学会或全局同步完成。

如果第 2 步后、第 3 步前中断，发送端重试，接收端识别重复后再确认。CLI `--stop-before-ack` 提供可复现的这个故障点，返回码 3 表示未完成；正常幂等重复不增加日志大小。

同步同时比较接收端当前持有的事件，不只相信发送端历史回执。接收端恢复旧快照、丢失曾确认的数据时，只要发送端仍保留事件，就可再次补传。相同 ID 的内容冲突始终报错。两个日志的节点 ID 必须不同，节点命名和文件可信性由本地调用者负责，没有远程授权。

## 上限与 CPU／I/O 成本

每日志最多 4096 个不可变事件、64 个 `(device, session)` 来源、8 个回执目标、16 MiB 文件；每批最多 128 条。满后明确拒绝，不驱逐已确认事件。没有压缩、保留期、遗忘、分页或无限离线积压能力。切换新日志必须由上层设计保留和同步策略，不能当成安全删除旧经验的许可。

索引、去重和同步使用内存 map/set；启动扫描整个有界文件，接收前复制当前索引以保证持久提交后的内存切换不再分配。当前不是数据库吞吐最优实现。每次 receive／ack 均强制同步，代价可能显著；上层可用批次减少写入次数，默认监听日志路径则每窗口提交一次，可能增加功耗或造成设备 overflow。未测量这些硬件成本，不把有界等同于低功耗。

`cpu-listen --journal PATH DEVICE` 是显式启用；默认不落盘。每次监听启动生成随机会话 ID，sequence 使用当前窗口序号；进程重启用新会话，旧事件身份不变。生成器不是配对认证机制，也不声称 UUID 标准合规。JSON 的非 null `durable_event` 在 receive 成功后输出，表示该窗口的特征事件已经提交；不是说原始音频已保存。后续 stdout 失败时事件可能已保存但调用方未看到确认，重同步仍需幂等处理。

日志耗时不包含在已有 processing_ms 中，不能据此评估持久化后的总延迟。输出后发生的物理断电行为、真实跨设备时钟和网络安全仍需下一阶段验证。

## 验证

- 批次冲突不部分插入；相同事件不重复写；乱序交付不丢低序号。
- 接收提交后中断、重启重试、持久回执、重复同步零增长、恢复旧接收快照后补传。
- 多个末帧截断位置恢复；完整帧损坏和节点身份不符时拒绝且不改文件。
- 单文件独占、4096 事件／64 来源／8 回执目标／16 MiB 与批次数量边界。
- 原生监听写入确认后被强制结束，重开和同步保留已确认事件；重启录音使用新 session。

这些是同机文件适配器和软件故障测试，不等价于手机／穿戴部署、真实断电测试或生产级分布式事务。

## 下一步

先设计版本化网络批次、身份配对与鉴权、可重放回执；再提供手机采集适配器。ChronoSynth 的学会事件必须由执行评估和技能版本产生，不能由收到音频、复制标签或自我描述触发。本阶段没有生成任何学会事件。

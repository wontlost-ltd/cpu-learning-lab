# ADR 0008：离线配对与原生 TLS 事件传输

## 状态与范围

P5 第二部分：macOS/Linux 原生网络参考适配器。默认构建不引入网络库；显式 `CPUAI_WITH_NETWORK=ON` 增加 OpenSSL 3 和 `cpu-link`。Windows 仍支持原有核心、监听与文件同步，网络构建当前明确拒绝该平台。

本阶段不新增视频、不实现手机／穿戴 App，也不把 P4 的真实麦克风、噪声和功耗验收标为完成。网络路径使用真实 TCP/TLS 测试，但设备部署、生产安全审计和 ChronoSynth 学会事件适配仍未完成。

## 离线配对与凭据生命周期

`cpu-link init NEW_DIR NODE` 创建新的服务器身份目录：P-256 私钥、自签名证书（有效期一年）、设备授权表。目录 0700，新凭据文件 0600；以独占创建避免覆盖或创建竞争。设备／节点名称继续使用 P5 ASCII ID 约束。

`pair DIR DEVICE NEW_BUNDLE` 是操作者在接收端执行的**离线配对授权**，不是远程匿名注册或六位码协议。生成 256 位随机设备密钥，在配对包中保存服务节点、设备 ID、服务证书 SHA256 指纹和密钥。通过操作者信任的私密渠道转交完整配对包；没有二维码、自动发现或云账户。程序不在命令行参数或正常日志中打印密钥。

服务器只保存设备密钥的 SHA256 摘要；配对包持有者可以作为该设备写入，因此它本身是敏感凭据。它不是硬件绑定，复制该包即可复制设备权限。私钥与客户端包没有口令加密，依赖本机用户／文件权限保护。最多 32 个设备身份槽，撤销保留槽位；同设备重新配对会轮换密钥并使旧包失效。

授权表使用独占锁和同目录临时文件、系统同步、原子 rename 替换。配对包先持久化再授权；操作中途失败可能留下尚未授权的包，命令报错后不能当作配对成功。没有跨文件全局事务。`revoke` 后，已有连接每一批提交前都会重新检查授权；该检查与日志提交持有授权锁，撤销命令遇到忙锁会报错，操作者应重试。已经提交的数据不会因撤销而删除。

## TLS 服务身份与设备鉴权

TLS 最低 1.3，禁用 0-RTT；使用 OpenSSL 的协议与密码实现，不自研密码算法。客户端在发送任何设备凭据前比较服务端完整证书 SHA256 指纹，并检查证书有效期。指纹来自可信离线配对包；不使用公有 CA 或 DNS 主机名验证，不进行首次连接自动信任。证书或私钥更换后需要重新配对，没有自动证书轮换协议。iOS 适配起新生成身份使用 P-256/SHA256，以满足 Apple TLS 互通；此前生成的 Ed25519 身份不自动改写，接入 Apple 客户端应创建新的身份目录并重新配对，接收日志可保留。

服务端不要求客户端证书；设备通过加密通道中的独立密钥鉴权。服务节点名、协议版本、设备 ID 和密钥必须匹配。密钥摘要使用恒定时间比较。每一批事件的 origin 必须是已授权设备自身，禁止该设备冒用或转发其他设备身份；payload 没有远程路径或任意命令字段。

这只证明对方持有授权凭据，不证明音频真实、标签正确或设备没有被攻陷。已授权设备仍能提交符合边界的虚假特征或标签；接收事件不直接执行教学或发布技能。

## 有界版本化传输

TCP 端点使用 IPv4 字面量，没有阻塞 DNS 查询。默认绑定 127.0.0.1；跨机器须操作者显式 `--bind LAN_IP`。不提供端口转发、外网部署、流量配额、自动配对或防火墙修改。

每个 TLS 应用帧由网络序 32 位长度和 UTF-8／ASCII 文本载荷组成。握手最多 2048 字节，事件帧最多 128 KiB；分配前验证长度。版本为 CPUAI_NET1 和 CPUAI_BATCH1；每批 1..128 条事件，每连接最多 32 批，对应现有最多 4096 条本地事件。

握手后传输批次，接收端完整校验、持久提交后返回 ACK，包含批次数量、新插入数量、原始载荷 SHA256 和服务节点 ID。发送端校验全部字段，再持久化本地回执。END/DONE 表示本连接完成；关闭连接不被当作成功回执。TLS 正常完成也不能替代应用确认。

`push` 每次都重新发送当前日志的**本设备**事件，接收端按稳定事件 ID 去重。这样即使发送端已有历史回执、接收端恢复了旧快照，也可以补回数据。代价是重复网络流量；尚无差量清单／Merkle 协商。其他设备的转发事件不发送，complete=1 仅覆盖本次本设备快照，不表示整个转发日志或全局同步完成。

接收提交后 ACK 丢失，客户端返回失败，重试时事件不会重复插入。`--drop-after-commit` 提供确定性的这个故障点。ACK 仅针对已提交批次；后续批次或 DONE 失败时，之前确认可保留，整次 push 不输出成功。

## 调度与限制

网络使用非阻塞 socket、poll 和 SSL WANT_READ/WANT_WRITE 状态；TLS 握手与应用收发共享一个连接绝对截止时间，默认 5000 ms，可设 100..60000 ms。客户端连接建立另有相同长度的截止时间，服务端等待新连接可以持续等待。

服务单线程串行处理，连接积压上限 8，操作者指定最多处理多少条连接。未经授权连接也消耗次数。没有按 IP 限流或抵抗拒绝服务的承诺，慢客户端会占用到超时；不适合作为互联网公开服务。文件系统同步调用不受网络 poll 截止时间强制中断，磁盘或驱动阻塞仍可能延长实际时间。

接收日志由服务器进程独占；停止服务后才能用 cpu-sync 查看或用另一进程访问同一日志。发送日志在 push 期间独占，仍需结束采集后补传。当前没有并发采集／同步数据库，也没有移动端后台调度。

## 验证

协议单元测试：版本、数量、来源绑定、重复 ID、截断、尾部垃圾。

真实回环 TCP/TLS 集成测试：离线配对、正确传输、证书指纹不符、错误密钥、设备冒用、版本／长度／截断错误、绝对收发超时、授权撤销与轮换、已有连接批次间撤销、129 条跨批次传输、错误 ACK 不写本地回执、提交后断线、重复补传零日志增长、旧接收快照恢复。

这些测试使用独立原生进程和真实 OpenSSL 连接，不是物理手机／眼镜／手表，不是安全审计或真实网络环境质量验收。

## 原计划的后续任务

手机采集端消费这个有界设备协议；之后扩展穿戴设备。ChronoSynth 适配须以执行评估和已验收技能版本生成学会事件，不能由网络收包、配对或标签复制触发。

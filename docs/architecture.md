# 目标架构

这是 CPU 优先持续学习系统的实验仓库。初始无用户领域示例，但具有明确的表示与搜索先验。当前仅实现有限算术 DSL 中的归纳，不是通用智能。

用户示例进入经验存储，归纳器在资源预算内提出候选；运行器执行候选；独立评估器检查未见任务；通过后才发布带来源与版本的技能。用户反例触发草稿重新学习；P3 发布层保留旧版本及其验收集，组合固定引用依赖版本，支持回放和回滚。

## CPU 设计约束

- 核心可离线运行，不要求 GPU、NPU 或外部 LLM。
- 每次任务只选择相关知识；索引和局部更新属于后续实现。
- 搜索、内存、时间与学习调度都有显式预算；当前有组合数、深度、唯一表达式数、候选数和示例上限，另有 PMR 图存储字节预算、协作取消及截止时间。
- 对输入流使用有界缓存和背压；这属于未来感知路径。
- 即时感知和后台巩固使用不同调度优先级。
- 先测质量与资源成本，再增加 SIMD、并行和量化。P2 使用 DAG、可续算生成器和局部筛选缓存；不以 CPU-only 本身作为高效证明。

## 模态与设备

目标 Observation 契约包含设备来源、模态、时间范围、时钟不确定性、内容引用和质量。不同模态保留自身结构，通过时间与反馈关联；不要求先全部转为文本。

可穿戴设备执行采集与轻量响应，手机承担本地融合，桌面可承担较重巩固。设备部署必须服从平台权限、续航和后台运行限制。当前没有实现这些适配器。

## 与 ChronoSynth 的关系

本仓库独立演进，不复制或重写 ChronoSynth 的管理面。未来复用其工件生命周期、影子评估、快照和来源思想。叙事或关键词覆盖不构成执行能力证明。

## 正确性边界

拟合示例不等于证明规律。候选、已评估技能和知识断言分开；评分声明必须带测试集版本与范围。P1 已实现有界多假设和独立测试；P3 支持受限算术技能的验收发布，尚无反事实验证或全局持久认证。

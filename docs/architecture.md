# 目标架构

这是 CPU 优先持续学习系统的实验仓库。初始无用户领域示例，但具有明确的表示与搜索先验。当前实现有限算术 DSL 归纳和用户教学的局部音频特征分类，不是通用智能。

用户示例进入经验存储，归纳器在资源预算内提出候选；运行器执行候选；独立评估器检查未见任务；通过后才发布带来源与版本的技能。用户反例触发草稿重新学习；P3 发布层保留旧版本及其验收集，组合固定引用依赖版本，支持回放和回滚。

## CPU 设计约束

- 核心可离线运行，不要求 GPU、NPU 或外部 LLM。
- 每次任务只选择相关知识；索引和局部更新属于后续实现。
- 搜索、内存、时间与学习调度都有显式预算；当前有组合数、深度、唯一表达式数、候选数和示例上限，另有 PMR 图存储字节预算、协作取消及截止时间。
- P4 音频观察流和连续 PCM 使用有界缓存、显式消费确认与背压。可选麦克风入口轮询设备帧，特征／推理在普通线程执行；尚无跨设备实时调度。
- 即时感知和后台巩固使用不同调度优先级。
- 先测质量与资源成本，再增加 SIMD、并行和量化。P2 使用 DAG、可续算生成器和局部筛选缓存；不以 CPU-only 本身作为高效证明。

## 模态与设备

目标 Observation 契约包含设备来源、模态、时间范围、时钟不确定性、内容引用和质量。不同模态保留自身结构，通过时间与反馈关联；不要求先全部转为文本。

可穿戴设备执行采集与轻量响应，手机承担本地融合，桌面可承担较重巩固。设备部署必须服从平台权限、续航和后台运行限制。当前有本地 PCM16 WAV、连续 PCM stdin 和可选 PortAudio 默认麦克风入口；显式时钟误差对齐仍需调用方提供时钟映射，没有实现手机／穿戴采集适配器。

## 与 ChronoSynth 的关系

本仓库独立演进，不复制或重写 ChronoSynth 的管理面。未来复用其工件生命周期、影子评估、快照和来源思想。叙事或关键词覆盖不构成执行能力证明。

## 正确性边界

拟合示例不等于证明规律。候选、已评估技能和知识断言分开；评分声明必须带测试集版本与范围。P1 已实现有界多假设和独立测试；P3 支持受限算术技能的验收发布，尚无反事实验证或全局持久认证。

## P5 可靠事件基础

设备特征和显式用户标签可记录为不可变 DeviceEvent，以设备／会话／序号去重。日志事务确认发生在平台文件同步之后；文件传输模拟接收端提交、发送端回执和重试。当前日志由单进程独占，采集结束后再补传；事件复制不等于模型应用、技能验收或 ChronoSynth 学会事件。

尚无网络身份认证、手机应用、跨设备时钟映射或生产级事件应用事务。P4 的真实设备和功耗验收不因可靠日志模块完成而跳过，详见 ADR 0007。

P5 的可选 macOS/Linux 网络适配器使用 TLS 1.3、离线配对包和逐批设备来源授权，沿用接收端持久提交／发送端回执。默认只监听回环地址；客户端证书指纹绑定在发送密钥前执行。没有远程自动注册、移动端部署或安全审计，参见 ADR 0008。

P5 的 iOS 采集端通过 C ABI 复用 C++ 音频、日志和协议，UI／麦克风权限／Keychain 由 Swift 与系统框架管理。实时回调只进入固定 SPSC 队列，背景 worker 完成特征与持久化，用户结束采集后使用 Apple TLS 客户端手动补传。后台与中断停止、不自动恢复；手机模型教学、穿戴和 ChronoSynth 适配尚未完成，详见 ADR 0009。

Apple Watch 作为受系统配对约束的伴侣采集源：本地提交后，经有界 WatchConnectivity envelope 进入 iPhone 源镜像日志，iPhone 提交后才回复 watch。之后以独立 watch 凭据向 Mac 提交。两层 ACK 不混淆，原件保留、重试去重；没有后台运行保证或学习副作用，见 ADR 0010。
